## 直播到底吃网络哪几项

直播和刷视频对网络的要求是两回事。看直播，你的手机在下载数据，用的是下行带宽；做直播，你要连续不断地把视频流往外推，吃的是**上行带宽**，而且是不间断、不能抖的那种。

第三方资料里普遍引用的口径大致是：720p 稳定推流的码率约 1～2.5Mbps，1080p 大约需要 3.5～5Mbps 码率，对应 6Mbps 以上的稳定上行更稳妥。延迟方面，一旦链路延迟超过 150ms，观众端就容易出现画面卡顿和弹幕滞后；丢包率超过 1%，卡顿就会变得肉眼可见。

还有一个常被忽略的点：家宽是典型的“下行快、上行慢”。100M 宽带的下行能跑满，上行往往只有 10～20Mbps，还可能被运营商动态分配。这也是为什么有人“在家测速很快，一开播还是卡”——测速app看的是下行，直播要的是上行。

## IEPL 是什么，为什么总和直播一起出现

IEPL（Ethernet Private Line，以太网点对点专线）的本质，是在你本地和海外出口之间拉一条不走公网、独享的点对点内网线路。你平时听到的 IPLC 也是同类思路，区别在底层实现：IEPL 基于以太网二层技术，IPLC 是传统国际专线租赁，对使用者来说体验差异不大。

和“中转机场”比，核心差别有三层。第一是路径：机场的流量要在公网上绕行，撞上国际出口拥堵就慢；专线在两端之间走的是内网段，跨境这段不参与公网 congestion。第二是资源：机场一个节点几百人挤，IP 被大量复用；专线 VPS 给你的是独享 IP——MKCloud 的每台机器分配 1 个独立入口 IP 和 1 个独立出口 IP。第三是波动：公网线路晚高峰掉速是常态，专线的延迟和速率曲线平得多。

不过要说清一个概念：MKCloud 标的"1～2ms"是**端内延迟**，也就是从国内入口到海外出口那一小段。你本地宽带到入口、出口到平台服务器的部分不在这个数字里。官方自己也在文档里反复强调“这不是你到目标网站的全程延迟”——这个口径，第三方测评倒是引用得挺老实。

## 几个常见问题

**用了 IEPL 直播就一定不卡吗？** 不一定。专线只保证“入口→出口”这段的质量，你本地宽带到入口那一段还是普通网络，上行不足、Wi-Fi 丢包照样卡。电脑开播尽量网线直连，手机开播离路由器近一点，这些老建议在专线方案里依然成立。

**机场真的不能用来直播吗？** 能，但有条件。轻量、偶发的开播用机场问题不大；固定时段的商业直播，共享节点的波动和 IP 复用是实打实的风险，第三方 TikTok 运营资料普遍把 0 播放和限流问题归因于网络环境，其中共享 IP 占比不小。
